# NDAX 直读分析与异常放行：整体修改方案

> 会议：2026-10-19，三轮讨论及用户后续裁决。此文是实施方案，不代表代码已修改。GPT、DeepSeek、MiniMax 完成第三轮；GLM 只完成第一轮，第二、三轮因模型接口 429 未响应。**用户的后续裁决优先于任何顾问建议**。

## 一、不可重开的产品约束

1. **输入权威**：主分析仅以 `.ndax` 为输入；每个 ndax 内的 `Step.xml` 直接给出配方脉冲档位，`NewareNDA.nda.read(ndax, software_cycle_number=False)` 给出实测时序。分析链不经 xlsx、不读 `2_xlsx`，不再由文件名或配置表决定分析档位。独立「ndax→Excel 导出」功能仍保留。
2. **报告不缩水**：原有 Result/Sample Excel、Word、CSV、JSON 和图像等交付物均保留，文件类型和交付用途不因输入源变化而取消；Word 指向报告 Excel 的链接也应保持有效。可补充缺失提示，不可将缺失伪装成零。
3. **profile 可选、只用于验证**：有 profile 时在点击分析前与 ndax 的 Step.xml 逐档比较（规范化单位、数量、值和顺序；相同档数不同值零容差）。不一致时提供「以 ndax 为准继续」，默认焦点「中止」；无 profile 不作为必填，按版本记忆的一次性免责声明。**不同 ndax 文件之间配方档位不一致为硬阻断，不给放行**。
4. **完成状态不作为阻断依据**：本阶段无中断 ndax 对照样本，ndax 一律按可继续分析处理；Step.xml 若有明确已完成状态可记录/通过，没有可用状态也默认放行。不得把「默认放行」写成「已证实测试完成」。
5. **点击分析后的实测异常**：某档位找不到脉冲、某通道/文件不能正常分析时，先处理整批并汇总全部异常；主线程弹框①问「是否停止整批」（默认停止），选继续才弹框②列出缺失后果并再次确认（默认中止）。拒绝即停止；确认后保留故障通道与档位的空位，正常数据继续处理。实测中位数偏差 `> max(1%, 0.5mA)` 是黄色质量告警，**有数据但偏离**；与「无脉冲/无数据」分型，不填空位、不混为同一种故障。
6. **版本和旧报告**：沿用 `SHA256.csv` 主/次版本号，例如同一输入成功分析后 UI 从 `1.0` 更新为 `1.1`。目标同名时**安全拒绝，不删、不覆盖、不另造 `_r2` 后缀体系**。只有全部报告成功产出才计入一次成功运行；失败或取消清掉本次独占创建的半成品，原有报告与已成功计次保持不变。
7. **日期和命名**：报告测试日期从 ndax 的**实测 `Timestamp`** 按统一规则确定一次；`Step.xml` 只用于配方档位，不用于推断实际测试日期。校验、规范化为 `YYYYMMDD` 后，下发唯一 `test_date` 和 `result_dir` 给所有写入器。内部临时目录统一小写 `v{版本}`，正式目录统一 `{YYYYMMDD}_v{版本}`。现有交付文件名中的字母大小写不为修路径而随意改变。

## 二、已核实的现状与变更依据

| 代码位置 | 现状及风险 | 目标 |
|---|---|---|
| `src/battery_analysis/ndax/converter.py` | 已用 `nda.read()` 读 ndax，并从 DataFrame 派生 Record/Step/Cycle 写入 xlsx | 抽取可复用的纯数据变换，主分析在内存复用；独立导出功能继续可用 |
| `main/business_logic/data_processor.py`、`utils/file_validator.py`、`main/managers/path_manager.py` | 扫描、验证或自动选中 `2_xlsx`；首个 xlsx 的文件名解析档位并写全局配置 | 扫描 ndax；档位取 Step.xml；去除主分析的 xlsx 路径约束 |
| `utils/processors/battery_analysis.py`、`utils/readers/xlsx_reader.py` | 主分析读 xlsx；失败文件可能从结果列表中过滤掉；`V{version}` 大写路径 | ndax 直读、固定输入序号保位；统一小写 `v` 和显式传入路径 |
| `utils/processors/pulse_matcher.py`、`utils/processors/data_utils.py` | 无匹配档位产生空列表；空数组 `filtered_mask[0]` 越界；未匹配行索引以 `0` 作哨兵 | 缺失用状态/`None` 表示；过滤空判；禁止缺失进零值计算 |
| `utils/writers/info_csv_writer.py`、`main/visualization/data_loader.py` | CSV 写端每档固定三行，空档写空行；读端 `if float_data:` 跳过空行，造成电池索引错位；Info_Plot.json 整体覆写 | 保持 CSV 固定行数，读端空行补占位；元数据一次写入本次决策与异常状态，避免覆盖留痕 |
| `main/workers/analysis_worker.py` | 两处目录同名即 `shutil.rmtree`；rename 失败时降级继续；`rename_path` 信号早于实际 rename | 删两处危险删除；碰撞拒绝；rename 失败算失败；仅成功后更新路径、版本 |
| `main/controllers/main_controller.py`、`main/utils/signal_connector.py`、`main/business_logic/version_manager.py` | `thread_end` 不论成功、错误、取消都触发 `analysis_completed`，并调用 `set_version()` | `thread_end` 仍无条件发以复位 UI；版本更新接**仅全部报告成功才发**的独立成功信号 |
| `utils/report_coordinator.py`、`utils/json_writer.py` | worker、coordinator、JsonWriter 独立取日期、拼 `{td}_v{version}`；Word docx 另写输出根目录 | 目录与日期单点决议、显式传参；docx 也纳入同名检查、本次产物登记和失败清理 |

日期分裂示例（根据代码分支推演，非真实 ndax 样本）：`test_date=20241020`，首条实测时间为 `2024-10-19 23:55:00`。当前 worker/ReportCoordinator 可指向 `20241020_v1.0`，JsonWriter 则按时间戳写 `20241019_v1.0`。新流程必须消灭这种分裂。

## 三、目标流程与数据契约

### 3.1 运行前（不读取整批实测时序）

- 确认输入 ndax 清单、项目目录及版本校验和已计算完成；由**ndax 文件集合**而非 xlsx 计算校验和，保持 `SHA256.csv` 的主/次计次格式与含义。文件列表、版本、profile 决策冻结为本次运行快照，避免运行时输入路径或异步校验和切换。
- 从每个 ndax 的 Step.xml 读取档位并核对跨文件一致；不能读出可靠配方档位的文件**不能靠猜文件名继续**，应提示格式/证据问题，由实施时明确其与「数据文件异常可放行」的边界（见末节）。
- 有 profile：逐档核对并在点击分析**之前**完成放行决策；无 profile：一次性免责声明记录在 QSettings 键 `validation/profile_disclaimer_version`，策略版 `2026.10`。不以 Step.xml 完成状态缺失阻断。

### 3.2 点击「分析」后（一次读取、先算不写）

- 每文件一次 `nda.read()`，在子进程内派生必要视图、脉冲匹配、电荷计算、实测偏差；尽快释放原始 DataFrame，主进程只累积按输入文件顺序排列的派生结果、状态与异常。**不得为弹框缓存整批原始 DataFrame，也不为正式分析二次读取 ndax**。并行度需按实际内存测试限制。
- 结果维度保持 `电池/文件 b × 配方电流档 c × 电压档 v`。某档无脉冲则该槽位为缺失、其余档保留；整通道/文件坏则保留该通道序号和名称，数据槽全为空。不得从结果列表过滤失败项，使后续电池顶替位置；不得把缺失当 `0` 参与统计。
- 将结构性缺失（缺脉冲、坏通道/文件）与质量告警（有数据但中位数偏差）分别汇总。冻结本次异常清单，供弹框、元数据和报告共用。经信号交给**GUI 主线程**弹两次确认；worker 不直接创建 QMessageBox。取消、关闭对话框、等待中取消均按停止处理。
- 确认停止时，不生成交付半成品，不占用成功版本；确认继续时，数据缺失在所有报告与图像中以「无数据/缺失（原因）」显示，统计注明有效样本量，不能写零值。全部有效数据皆缺失时是否仍强制生成全套报告，需要以报告模板实测明确处理边界，不能假称现有绘图/Excel 模板已支持。

### 3.3 保位格式与留痕

- `Info_Image.csv` 保持现有每电池 `1+3×档位数` 行，不插入 `MISSING` 行、不把 `N/A` 混进数值列。缺档三行为空行；读取端必须对每行 append 对应空占位，确保每档的电池个数恒等于输入电池数。用户可见的缺失文字应出现在报告和图表，而非 CSV 的数值栏。
- `Info_Plot.json` 一次组装本次 `current_levels`、每文件/通道与档位状态、异常清单及 `profile_validation`（`result`、`mismatch_type`、`decision`、`policy_version: "2026.10"`）。写入时只指向本次明确的结果路径，后续写入不得把校验决策覆盖掉；中止但无报告目录时的操作事件可记独立运行日志，不伪造成功结果。
- 同档数不同档值仍按 0 容差比较；实测中位数阈值按此前裁决 `max(1%, 0.5mA)`，具体计算应与 ndax 配方设定值比较，不用 profile 替代基准。此基准为方案建议，真实样本验证前不应扩大成其他质量判定。

## 四、安全提交与版本推进

1. **路径一次决议**：统一从本次 ndax 实测 `Timestamp` 选取测试日期（建议取整批最早的有效实际采样时间，跨日文件需提示），严格校验合法日期；确定 `version` 后生成唯一目录及 Word 文件路径，向 BatteryAnalysis、ReportCoordinator、JsonWriter 等显式传参。若实测日期无法确定，拒绝生成带猜测日期的报告，提示用户核对数据。
2. **创建前拒绝碰撞**：本次中间目录、正式 `{date}_v{version}`、输出根 Word docx 任一预已存在，不删除/覆盖/自动后缀；给出具体路径提示。现有代码中两处「存在即 `rmtree`」必须彻底删除。目录创建时记录**本次确实新建的路径**，不能按名字猜所有权。
3. **只清本次半成品**：失败、取消、rename 或某报告写入失败时，根据本次新建文件/目录白名单删除它们，包含输出根目录下本次生成的 docx；旧版本目录、已有 docx、`SHA256.csv` 成功次数都不能触碰。清理失败要列出残留路径供人工处理，不得以模糊通配符清理整个输出目录。异常不能落入当前「rename 失败后仍继续写报告」的降级分支。
4. **成功门槛**：全部现有报告、图像和核心元数据写完并检查文件存在/非空，且未取消、路径与本次决议一致，才通知 GUI 成功并调用 `set_version()`。`thread_end` 继续无条件通知 UI 复位；失败/取消不触发成功信号，次版本不递增。`get_version()` 为新校验和预登记的 `times=0` 与成功后 `times+1` 是不同动作：失败时不得新增成功计次，预登记行如何长期保存沿用现状。
5. **硬崩溃边界**：进程被强杀/断电时进程内 finally 无法清理；下次若发现同名残留，应安全拒绝并告知路径，不可自动删除无法证明属本次运行的目录。

> 现状是 Windows 可能将大写 `V{version}` 与小写 `v{version}` 视为同一目录；大小写敏感文件系统会拆开。统一使用小写 `v`，并用同一显式路径，避免按平台碰运气。

## 五、实施顺序与验收

| 阶段 | 改造 | 必须验收 |
|---|---|---|
| P0 防崩溃与保位 | `filter_data` 空输入；脉冲缺位非零；并行结果按输入索引保位 | 空档/坏通道不崩，后续电池不移位，统计不含假零 |
| P1 日期与路径单点化 | 确定统一 `Timestamp` 日期、`result_dir`、小写 `v`；所有写入器消费相同路径；把根目录 docx 纳入清单 | 原先不同 fallback 日期输入不再生成第二目录；Excel/Word/JSON 归属正确 |
| P2 输出与版本安全 | 删两处同名删除；同名拒绝；仅本次产物清理；成功信号与版本递增拆分 | 失败/取消/重试版本不变，原报告字节不变；成功两次连续走 1.0、1.1 |
| P3 ndax 直读 | 提取 ndax reader/视图，Step.xml 档位解析，`nda.read()` 一次读取，xlsx 输入链退出；版本校验源切 ndax | 真实样本：直读与旧链数值结果逐槽对照；独立导出与 Excel 报告测试继续通过 |
| P4 运行前验证及运行后确认 | profile 可选校验；跨 ndax 配方一致；点击后异常冻结与主线程两次确认 | 无 profile/同值/异值/档数差异/多 ndax 分歧、弹框顺序及关闭/取消分支全覆盖 |
| P5 报告缺失语义 | CSV 空行读端补位；图表/Excel/Word/CSV/JSON 空位与异常留痕 | 全套报告一个不少；缺失显示原因，不写 0，不挪电池，统计只用有效值 |

**故障注入回归**：在分析中、第一次/第二次确认后、rename 前后、Excel/Word/CSV/JSON/图像各写一半时注入失败/取消；分别断言次版本不变、仅本次路径清理、旧报告及 docx 不变；正常完成断言所有文件齐全再计次。检查 `analysis_worker.py` 无「目标存在即删除」、所有写入器不再独立拼日期目录、内部路径无 `V{version}` 大写旁路；GUI 对话框仅在主线程。ndax 性能和内存应以真实文件测量，不以顾问估算作为验收数值。

## 六、实施前需要真实数据或明确约束的边界

- **Step.xml 实际字段/格式**：会议决定直接用其配方档位，但仓库尚无解析器及可供核验的真实 ndax fixture；完成状态字段存在性也未证实。先用真实文件建立解析测试与配方一致性样本。`Step.xml` 不可读且无法确认档位时如何允许/拒绝是输入可信性边界，不可凭文件名伪造。
- **多文件跨日**：日期来自实测 Timestamp。本文建议以最早有效采样时间确定整批日期并提示跨日，属于明确的实施建议，尚非用户单独拍板的具体规则。
- **全部通道均无可用数据**：用户允许二次确认后继续，但现有绘图和 Excel/Word 模板能否生成有意义的全空报告未验证；实现时须测试并明确失败提示，不可宣称已经支持。
- **中断/崩溃后的残片**：正常失败/取消可在 finally 清理；硬崩溃不能保证自动清理，只能安全拒绝碰撞并提示人工处理，除非后续明确授权恢复功能。

## 会议结论

按 **「Step.xml 定档位、ndax Timestamp 定日期、nda.read 定实测；路径一次决议；一次读取先算不写；点击前 profile 校验、点击后异常两次确认；报告全部保留；成功才计次、失败只清本次产物」** 实施。GLM Round 3 未响应，不能据此声称四家在新版本方案上全票一致；MiniMax Round 3 仍出现 `_r{n}` 建议，已按用户的后续裁决排除。
