# v5.0.0 — NDAX 原生分析与数据质量追溯

## 1. 版本定位与覆盖范围

v5.0.0 将主分析从“NDAX 转 Excel，再读 Excel”切换为“直接读取 NDAX，在内存中构造分析数据”。这是输入依赖、配方权威、历史校验和和交付安全语义的主链路升级，不是仅优化读取速度，也不是重写全部容量公式。

本说明覆盖 v4.1.0 版本更新提交 `7472e27` 之后的功能和维护变化，包括已提交的报告完善、型号提示、NDAX 直读，以及后续真实数据验证中补充的版本管理、异常分级、类型同源、日志和过程审计修复。不是只罗列最后一轮补丁。

- **软件版本**：`5.0.0`，唯一版本源为 `src/battery_analysis/_version.py`；包版本、界面版本封装、构建脚本从此读取。uv 的缓存键同时追踪 pyproject 和版本源，避免动态版本变化后安装包元数据仍沿用旧版本。
- **报告版本**：界面中的 `4.0`、`4.1` 等，是单独的报告交付编号；升级软件不把旧报告重编号，也不清零成功次数。
- **交付状态**：源码与文档准备升级，不等于已经打包、创建 tag、推送或发布安装程序。

## 2. 主分析输入与读取流程

| 项目 | 旧流程 | v5.0.0 |
|---|---|---|
| 主分析输入 | 预先转换的 `.xlsx` | 原始 `.ndax` |
| 常规输入目录 | `2_xlsx` | `1_ndax` |
| 中间文件 | 主分析依赖磁盘 Excel | 不要求生成中间 Excel |
| 内部分析视图 | 从工作簿读 Cycle / Step / Record | 从 NDAX 在内存构造兼容视图 |
| 样本数量 | 扫描 Excel 文件数 | 扫描 NDAX 文件数 |
| 输入校验和 | Excel 文件集合 | 自然排序后的 NDAX 文件集合 |
| 输出 | Excel / Word / CSV / JSON / PNG / SVG | 继续保留 |

- 选择 Test Profile XML 后，常规目录布局下输入自动指向 `1_ndax`，输出仍为 `3_analysis results`；也可直接指定含 NDAX 的输入目录。
- 文件按自然顺序处理，运行前校验本次输入集合，避免刷新后又改了输入却使用旧校验和。
- 每个 NDAX 读取后构造 Cycle、Step、Record 兼容视图，保留既有脉冲匹配、容量与绘图处理链的接口和数值约定。
- 主分析不再读取 `2_xlsx`。只有 Excel、没有 NDAX 的旧项目不能直接按原方式运行主分析，需要找回原始 NDAX；这不表示所有内部 Excel 读取能力都被删除。
- 独立 NDAX→Excel 导出工具继续保留，供检查原始记录或其他用途使用，不是主分析的必经步骤。

## 3. 配方电流档位与 Profile 对照

### 电流档位的唯一权威

- 从每个 NDAX 内部的 `Step.xml` 读取放电脉冲电流，按配方声明的顺序保留。
- 不再从文件名中的 `(15-6mA)`、配置查表或用户手动电流列表替代主分析档位。
- 检查配方脉冲数量、节点、有效数值、重复档位等。无可靠档位、配方损坏或无法解析时明确报错，不静默猜测。
- 同批所有文件的电流档位和顺序必须一致；不一致时列明相关文件及档位，拒绝混批分析。

### 外部 XML 的作用

- Test Profile 作为独立对照来源，而不是覆盖 NDAX 内嵌配方。
- 档位数量或值不一致时，默认不继续；用户可明确选择继续使用 NDAX 的 Step.xml，选择及失配类型进入过程记录。
- 未选择 Profile 时可按 Step.xml 分析，但需确认说明；当前确认策略版本下的说明确认会被记住。
- 文件名仍用于型号、厂家、成组方式、批次等非档位信息。配方校验不等于验证实测脉冲时序满足全部试验标准。

### 截止电压与电流分开管理

- 报告截止电压继续使用软件配置的超集，本次样本为 `2.6 / 2.5 / 2.4 / 2.3 / 2.25 / 2.2 / 2.1 / 2.0 / 1.8 V`。
- 不从 NDAX 的停止电压或保护电压推导报告截止档。
- 不切换为 PDF 普通 6 档/Hermes 7 档，以保留用户确认的报告列和图片范围。

## 4. 数据缺失、异常分级与人工放行

缺失表示某个文件在某个电流×电压格没有可用测量结果，不代表该电池容量为零，也不一定表示文件损坏。

| 情况 | 当前行为 | 记录方式 |
|---|---|---|
| 非判定必需格无匹配脉冲/容量 | 自动继续，不暂停批次 | `missing_pulse`、分类、有效样本数、完成告警 |
| 判定必需格缺失 | 必须人工明确放行 | 原始异常、`required_judgment_missing`、确认结果 |
| 分析档位列表缺少必需电流/电压格 | 必须人工明确放行 | `required_slot_missing` 和缺失档位 |
| 单文件读取/分析失败或没有有效时间戳 | 可分析阶段的文件错误需人工放行，保留该文件位置 | `file_error`、具体原因 |
| 运行前 Step.xml 解析失败/同批配方不一致 | 预检查拒绝，不进入异常放行来绕过配方 | 校验错误、应用日志 |
| 整批没有有效实测时间戳 | 明确失败，不允许放行生成无可靠日期报告 | 分析错误、日志 |
| 跨日 | 不新增阻断 | `cross_day`、起止时间 |
| 可识别电流的实测中位数偏差 | 质量告警留痕，不改配方档位 | 电流、偏差及异常详情 |
| 两个容量输入不同 | 不擅自改值或中断 | `capacity_basis_difference` 及当前计算依据 |

- 判定必需格与报告沿用同一套规则来源，包括 Hermes 的 2.5V 格；无法派生时当前保守检查最高实测电流×2.25V。这是缺失检查策略，不是电池类型的默认回退。
- 缺失容量保留为 `None`，不补零、不插值、不外推；原有有效数值、曲线采样点、计算和绘图算法不因放宽普通告警而改变。
- 对已识别脉冲档的实测电流取绝对中位数，偏差大于 `max(配方电流×1%, 0.5mA)` 时记录质量告警；仍按配方档位分析，不用偏差重写档位。
- `Step.xml` 未给出本程序可用的“试验已完成”证明；默认继续或人工放行均不等于已证实测完。
- 文件失败保留槽位，避免后续文件前移导致样本名和数据错位。
- 报告按格统计有效样本。保留原统计对 `None` 和 `0` 的排除规则，不把现有数值 0 重新解释为新增测量。
- 人工放行不证明试验完整；分析成功仅表示交付物生成成功，不等于电池合格。

### 异常交互

- 使用受屏幕尺寸约束的对话框，详情为只读、可滚动文本，不再因长异常列表把按钮挤出屏幕。
- 明确展示文件、脉冲电流（mA）、截止电压（V）、受影响文件数和槽位数，不再显示难以区分的重复电流值。
- 保留“检查详情后继续，再确认后果”的两步放行；默认停止，关闭/取消不作为同意。
- 普通缺失只在原有完成提示中汇总，不再额外弹确认框；逐条详情仍在日志及 JSON 中。

## 5. 报告内容、统计与已有判定完善

以下包含 v4.1.0 后、直读改造前已经实施的报告修复，不是这轮放宽告警时重新改公式：

- 报告结果支持 **Pass / Fail / Incomplete**；无有效数据的判定格不能直接聚合成 Pass，Word 概览支持“不足以验证”的文案。
- 2.25V 判定位置使用容差匹配；旧兼容路径缺少目标位置时记录回退说明，而不是假装匹配成功。
- 历史单点判定增加单样本最小值条件及告警；PDF 对照规则保持最小值 ≥ 阈值、μ−2σ 严格 > 阈值。
- 统计输出有效样本数 `counts`；单样本采用 σ=0 并标注，不能据此宣称样本充分。
- Result 表缺失位置写 `No data` 及原因；空统计格写 `No data (n=0)`。Sample 对空格不写容量比例公式，避免文本参与计算产生 `#VALUE!`。
- 继续生成 Result Excel、Sample Excel、Word、CSV、JSON、箱线图和过滤/未过滤负载电压曲线（PNG/SVG）。
- 分析日期、目录、文件名及报告内链接使用一致的本批实测日期，不再借用文件修改时间凑日期。

### 保留的判定边界

- 部分必需样本缺失后，人工放行的报告仍可能按剩余有效样本得到 Pass；当前不新增“必须全部样本齐全”的规则。
- 部分必需档位无法匹配时，报告层仍存在历史跳过/单点回退行为；分析层的缺失确认不是重写报告判定。
- 截止电压超集、容量依据、缺样本后的统计/Pass-Fail 口径均按用户决定保留，后续有明确要求再调整。

## 6. 电池类型与容量来源

### 类型同源，输出不猜测

- JSON、Word 及报告协调路径统一使用点击分析时提交的 `TestInfo.battery_type`（GUI Battery Type）。
- 修复把“型号”错当“类型”传入转换器、匹配失败默认为 `CoinCell` 的历史问题。
- 共享转换只把已知类型名称规范化为编码，例如 `Pouch Cell` → `PouchCell`；类型为空或未知时明确报错并显示问题值，不默认成其他类型。
- 这描述的是报告输出的类型来源；不将其扩张为“所有配置派生逻辑都已重写”。已有规则辅助界面填写的逻辑仍需用户确认。
- 新生成的 CP5022121 JSON 已验证为 `PouchCell`；不自动改写旧报告。

### 两种容量都是配置输入，不是本程序实测结果

规则格式：`型号/成组方式/Datasheet容量/Calculation容量/要求可用容量/CC电流`。

- 第 3、4 段分别填入两个容量输入框，用户可分别修改；运行时取界面快照。
- `CR2450/1S1P/600/550/380/1.0` 配了两个不同值；`CP5022121/1S1P/3500/3500/85%/10` 两者相同。
- 没有“600 自动算成 550”的过程，不能无证据解释历史差异是温度降额或实测修正。
- 当前百分比要求容量换算和报告分档仍使用 Calculation；PDF 写 datasheet QNOM，两值不同时可能存在口径差异，当前只记录，不自动切换。
- 未实现自动读取/核验厂商 datasheet，也未新增电池寿命估算模型。

## 7. 手动报告版本、校验和与成功计次

- 输入集合校验和改为自然排序的 NDAX 内容，仍保存于输出根目录 `SHA256.csv`。
- 开始分析前要求校验和就绪、对应记录存在、成功次数合法；输入发生变化时要求刷新，不使用过期快照。
- **允许手动报告版本**：必须不低于当前自动基线与输出目录已有交付版本的最高值，并且尚未使用。
- 按数字分段比较，而不是字符串大小；`4.01` 与 `4.1` 视为同一版本。最低版本为 `4.0` 时，`1.08` 不合法。
- 已交付版本检查跨测试日期生效；不能因为换日期就重复使用同一报告版本。
- 手动输入不会仅因为不等于自动建议值就被拒绝；记录实际本次使用版本，成功后保留手动版本并参与后续建议计算。
- 预登记新输入时 `times=0`，仅在交付物检查成功后增加成功次数；失败、取消和拒绝放行不冒充成功。
- 账本采用临时文件加原子替换写入，降低失败写入破坏既有计次的风险。
- 旧 XLSX 校验和与 NDAX 校验和不是同一数据源，首次迁移需要重新登记/刷新；旧行不自动迁移、清洗或删除。

## 8. 输出防覆盖、取消与日期

- 本次临时版本目录使用独占创建；最终日期目录和 Word 文件已存在时明确拒绝，不删除旧结果后重跑。
- Word 位于版本目录外，也单独做路径占用保护；目录与 Word 统一使用实测日期。
- 正常失败/取消只清理本次运行自己新建的目录和 Word，不递归清理项目根目录或历史交付。
- 任务结束会复位运行状态；等待 GUI 放行时支持协作式取消。
- 成功前检查必需交付物非空及关键文件齐全：Result/Sample Excel、CSV、JSON、Word、PNG/SVG，以及指定曲线源数据和过滤/未过滤曲线文件。检查不是对每份报告内容做完整合规认证。
- 一次成功运行只发一次成功信号后计次。
- 本批日期取最早有效实测采样时间；跨日单独记录。不使用系统当天、文件修改时间或猜测日期替代。
- 硬崩溃后的残留不自动恢复或删除，也不自动追加 `_r2`。应核实路径后手动处理或选新版本。

## 9. 日志与过程 JSON

应用日志使用 `battery_analysis.*` 命名日志器，补齐预检查、启动、等待确认、用户决定、日期、路径占用、写入、交付检查、失败堆栈、取消和清理失败等关键阶段。Windows 默认日志目录为 `%LOCALAPPDATA%\BatteryAnalysis\logs`。

`Info_Plot.json` 保留原始 `anomalies`、`file_statuses`、Profile 校验和逐文件/逐格状态，并新增：

| 内容 | 用途 |
|---|---|
| `battery_type` | 提交的电池类型文本 |
| `analysis_audit.input_context` | 输入快照来源、型号、类型及规范编码、两种容量、容量依据、声明样本数/文件数和 Profile 校验 |
| `analysis_audit.classification` | 每条异常详情、分类、是否要求人工确认 |
| `analysis_audit.required_judgment_cells` | 当前必需判定电流/电压格 |
| `analysis_audit.confirmation` | 无需确认、允许、或未连接回调的审计状态 |
| `analysis_audit.slot_sample_counts` | 每格电流、电压、有效样本数和预期输入文件数 |

日志逐项记录分类和缺格覆盖率，不只记录“有告警”。拒绝放行时不交付过程文件，但日志保留请求和拒绝结果。记录覆盖当前程序已检测到的问题，不意味着能发现所有异常。

## 10. 表单、配置、导出与其他配套变化

- 未识别成组规格方法时，原有 `1S1P` 默认行为增加 5 秒倒计时提示，请用户检查；不是未提示就当作文件已声明。
- 型号未配置时统一提示补充配置；`battery.missingRulesNotice.enabled` 控制启用，`timeoutSeconds` 默认 3 秒。与规格方法默认提示合并，避免重复打断。
- 修复重复信号连接导致同一提示出现两次。
- 冷冻语境判定收敛，文件名、规则、要求容量、温度信息由共享逻辑处理；构造方式识别支持中文“叠片/螺旋”。这不是增加完整温度合规验证。
- 独立转换工具的 Record 超过 Excel 单表 1,048,576 行上限时分成 `Record`、`Record_2` 等；兼容读取按名称拼接，避免单表截断。
- 修复 PyQt6 自定义字体注册方式，使配置字体能够实际加载；修正相关 Qt 枚举用法。
- GUI 自动测试统一离屏运行，恢复适用测试并清理已失效的跳过项；增加 PDF Golden 回归、配方读取、输出安全、版本比较、异常确认、同源类型及审计测试。
- 发布流程修复 Python 环境安装、以上一个 tag 为起点的发布说明范围、重复 Release 的处理以及 Gitee tag 同步问题。
- 仓库内 roadmap 网页修复遗漏的共享样式工具、TypeScript 6 配置、组件依赖 API 和 lint/build 问题；依赖更新包括 `brace-expansion`、`source-map-js` 和 `postcss-selector-parser`。这些是配套网页/发布维护，不是分析算法变化；本轮未重新执行网页构建或远端发布。

## 12. 升级操作与排错

1. 备份项目报告和 `SHA256.csv`；关闭旧进程再启动新版，运行中的窗口不会热加载源码。源码运行按当前 pyproject 要求使用 Python 3.14 或以上，执行 `uv sync --all-extras` 更新环境和动态版本元数据；这不是要求用户用脚本改写报告账本。
2. 输入选择 `1_ndax`，确认文件存在；只有 `2_xlsx` 时找回原始 NDAX。
3. 检查界面型号、类型、成组方式、两个容量、温度、人员和输出路径；必要时先补 Rules。
4. 刷新/等待 NDAX 校验和登记，选用不低于最高版本且未占用的报告版本。
5. 有 Profile 时检查失配提示；没有 Profile 时理解并确认使用 Step.xml。
6. 普通缺失可完成；需要放行的异常先阅读明细，不能将继续分析当作完整性证明。
7. 完成后核对输出、`No data`、有效样本数、`Info_Plot.json` 审计和日志；旧文件不自动修订。
