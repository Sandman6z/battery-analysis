## 一、已验证的事实（风险判断的基线）

| 项目 | 结果 |
|---|---|
| 直读 vs 旧 xlsx 链逐槽对照 | 9 电池 × 36 档电荷值完全一致；位置、时间戳、三视图行数一致 |
| 全量 9 文件端到端 | 20.8s，峰值内存 192 MB，19 个报告文件产出，成功信号 1 次 |
| Step.xml 档位 | 9 文件全部 `[30, 26, 15, 6]`，与 profile 逐档 0 容差一致 |
| 实测缺失 | 37 个 (电流档 × 电压档) 无脉冲 → 弹框 1 次、空位保留、报告写 `No data` |
| 实测跨日 | 单文件跨 `2025-06-10 → 2025-07-07`，日期取最早 `20250610`，已留痕 |
| 自动化 | 865 passed，ruff 全绿 |

结论：**主链路（读取→分析→报告→成功计次）在真实样本上无已知功能缺陷**。下列为残余风险。

## 二、风险清单（按严重度排序）

### R1 · 高：GUI 交互未在真实界面手工验证
- 现状：两次异常确认、profile 失配中止、同名拒绝、失败清理均由单元测试与脚本模拟信号覆盖。
- 风险：Qt 信号排队/线程调度（worker 阻塞等 GUI 应答）在真实事件循环中可能出现死锁或提前超时路径，测试环境模拟不到。
- 影响面：点击分析后卡住不弹框，或弹框后 worker 不恢复。
- 建议验收：真实界面跑一次含缺脉冲样本（现有样本即可），确认弹框顺序、关闭/取消、继续三条分支；再人为占用同名目录测拒绝路径。

### R2 · 高：全部数据缺失时的报告未实测
- 方案 §6 明确要求"实现时须测试并明确失败提示，不可宣称已经支持"。
- 现状：缺档级缺失已验证（写 `No data`、统计 `n=0`）；但**所有通道全坏/全无脉冲**的极端场景，绘图、Sample Excel、Word 模板是否产出有意义文件**未测**。
- 影响面：全空批次可能抛异常→按"失败"清理全部产物，用户看到空结果而非明确提示。
- 建议：构造一个全部档位无脉冲的 ndax 或故障注入跑一次，明确是"成功产出空报告"还是"明确失败提示"。

### R3 · 中：黄色质量告警阈值缺真实触发样本
- 规则：实测中位数偏差 `> max(1%, 0.5mA)` 判为偏离。
- 现状：现有样本实测中位数与配方完全一致，**阈值逻辑从未被真实触发**，仅有代码路径，无回归样本。
- 影响面：阈值过松→异常放行；过紧→正常批次被标黄干扰判断。
- 建议：找一个电流档位有系统偏差的历史样本验证，或明确该告警暂不上线。

### R4 · 中：SHA256.csv 校验和语义切换导致版本需刷新一次
- 变更：校验源从 xlsx 集合切到 ndax 集合（自然排序拼接）。
- 后果：**旧记录里的 xlsx 哈希与新 ndax 哈希永不匹配**；首次在旧项目目录上分析会提示"checksum absent / version stale"，需刷新版本 → 新增一行 `times=0`，主版本号顺延。
- 长期风险：`SHA256.csv` 会永久残留旧 xlsx 时代的无效行，主版本号与"实际分析次数"的直观含义出现历史断层。
- 需拍板：是否迁移/清洗旧记录（方案要求"预登记行如何长期保存沿用现状"，故当前未清理）。

### R5 · 中：跨日日期规则是方案建议，未经用户单独裁决
- 现状实现：整批取**最早有效实测时间**决定 `test_date`，跨日写入 `cross_day` 留痕，不弹框。
- 方案 §6 标注该规则"属于明确的实施建议，尚非用户单独拍板"。
- 影响面：若贵司规则是"按结束日/按开始日/跨日必须人工确认"，报告目录日期会不合规。
- 需拍板：确认跨日取最早时间 + 只留痕不确认，或改为弹框确认。

### R6 · 中：内存与并行策略仅单点实测
- 实测：串行读取，单进程峰值 192 MB（9 文件，单文件约 48 万行）。
- 风险：文件行数大一个量级（更长周期、更多采样）时峰值近似线性增长；当前**串行**是按"先测再并行"的选择，尚未在更大样本上验证是否需要并行或分批。
- 影响面：极大文件可能触发内存压力或耗时不可接受。

### R7 · 低-中：Step.xml 依赖 Neware 导出格式稳定
- 依赖点：ndax 是 zip，根节点 `Step.xml`（GB2312），档位取 `Step_Info/*/PulseData/PulseN@Value` 负值，校验 `Count` 与子元素数一致。
- 风险：BTS 客户端升级改结构（编码、节点名、多段 PulseData）→ 解析直接失败并阻断分析（fail-closed，不会静默用错档位）。
- 缓解：已有 `tests/battery_analysis/ndax/test_reader.py` 覆盖 Count 不符/编码/档位顺序；但无多版本 BTS 导出样本做兼容矩阵。

### R8 · 低：弹框文案与 i18n
- 两次确认弹框目前为英文硬编码，未接入 `i18n` 翻译表；`locale/` 里无对应词条。

### R9 · 低：`file_service.delete_directory`（含 `rmtree`）仍存在但无调用方
- 非本次引入、不在分析链上，按"不动无关代码"保留。若未来有人接线到自动清理，会重新引入危险删除，需在评审中盯住。
