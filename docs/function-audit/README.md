# 函数去重梳理记录

## 目标与原则

目标是**同一业务规则只有一份权威实现**，不是强制“一个功能只能有一个函数”。UI 入口、兼容适配器可以保留多个，但把规则委托给同一实现。单位、精度、异常处理、线程归属不同的函数，即使相似度很高，也不能直接合并。

已完成全量语法盘点、候选组核查、分析入口校验和 NDAX 文件发现的功能统一，以及一批已断开功能链的删除。功能修复见 [functional-review.md](functional-review.md)，退役清单与兼容影响见 [retired-features.md](retired-features.md)。**没有完成全部 985 个函数的逐行语义审查，也不保证找出所有异名、跨层或动态调用的重复功能。**

## 可复现方法

```sh
uv run python scripts/audit_functions.py
uv run pytest -o addopts= --import-mode=importlib --ignore=tests/manual -o log_cli=false -q --tb=short
```

扫描工具只用标准库，不导入或执行被扫描的业务代码，不自动合并函数。

1. 用 AST 枚举 `src/**/*.py` 的全部普通函数、异步函数、方法及嵌套函数；记录限定名称、起止行与函数内调用表达式。
2. 去掉函数首部文档字符串，按 AST 函数体筛出完全相同实现。
3. 对同名函数，或共享至少两个调用表达式的函数，用 AST 字符串相似度筛选候选（阈值 0.9）。避免人工两两比较所有函数。
4. 少于 4 个 AST 语句的短函数不列为重复候选，减少 getter、适配器、抽象方法噪声；仍完整收入函数清单。排除外层函数与其自身闭包的比较。
5. 人工检查调用方、输入/输出、异常、线程及可变状态，再决定合并、复用或保留；修改后做回归测试。

工具的边界：调用表达式不是解析后的调用图，`self.method` 无法仅凭语法定位具体对象；Qt 信号、反射、插件、变量改名和不同算法实现也可能漏检。高相似度不是可互换证明，低相似度也不是无重复证明。

## 第一阶段：已实施的五组实现去重

### 1. 后台任务派发

- 原位置：`DataProcessor._run_async`、`VersionManager._run_async`。
- 权威实现：`TaskManager.run_async`。
- 两个旧入口保留，只做委托，兼容现有业务调用和测试替换点。
- 保持“连接回调 → submit → 线程池启动”的顺序，原有生命周期、取消和信号回调机制未改。
- 新测试覆盖成功/异常、有/无回调、参数透传、进度回调、快速完成时的连接顺序和活跃任务释放；原有取消测试继续通过。

### 2. 初始化默认策略

移除以下五个类中仅 `return True` 的 `can_execute` 覆盖，直接继承 `InitializationStep.can_execute`：

- `BasicAttributesInitializationStep`
- `EnvironmentInitializationStep`
- `ServicesInitializationStep`
- `StylesInitializationStep`
- `UISetupStep`

保留其他带依赖检查的 `can_execute`，不改变初始化顺序及前置条件。新增参数化测试确认继承和行为。

### 3. 状态栏切换

- 原位置：`MenuManager.toggle_statusbar_safe`、`WindowSetup.toggle_statusbar_safe`。
- 权威实现：`menu_manager.toggle_statusbar`。
- 两个旧入口保留，复用同一规则。
- 有菜单动作时按勾选状态显示；无动作时反转可见性；无状态栏时不操作。
- 新测试覆盖两个入口及上述全部分支。

### 4. 无调用的设备信息读取副本

删除 `ReportCoordinator._get_equip_value`。它在 `src`、`tests` 中没有调用者；实际设备信息读取由 `WordFrontMatterMixin._get_equip_value` 完成。

保留实际读取函数，新增测试验证字符串、列表、元组、缺失键及不支持类型的回退行为。该私有方法如被仓库之外的脚本直接调用，需改用实际 Word 写入器；没有给私有死代码再加兼容层。

### 5. Word 模板占位符

- 原位置：`WordReportWriter._init_replace_placeholders`、`ReportCoordinator._build_replacements`。
- 权威实现：`report_coordinator.build_word_replacements`，沿用该模块既有的共享报告函数位置，未增加模块或继承层次。
- 保持文本/图片占位符顺序、电池类型校验、四个延迟填充值、自定义颜色及空电流列表行为。
- 颜色/电流说明由重复字符串累加改为 `join`；每次返回独立列表，避免不同写入器相互污染。
- 新测试覆盖两个调用方的一致性、空/单/多电流、自定义颜色及颜色数量不足的异常。既有电池类型来源测试继续通过。

## 当前 4 对相似候选的处理结论

编号对应当前 `candidates.json`。此前保留的占位命令、Presenter、旧验证服务、未使用 UI 框架和异常类，在用户授权清理遗留功能后，已按功能调用链核实并退役；不再仅因它们有单元测试而保留。

| 候选编号 | 函数组 | 结论及理由 |
|---|---|---|
| 1 | `validate_version` / `validate_input_path` | 保留 UI 适配入口，分别调用统一的版本和目录规则。 |
| 2 | `get_all_values` / `has_config_key` | 保留。配置读取与存在性判断的返回契约、失败默认值不同。 |
| 3 | `copy_file` / `move_file` | 保留。复制与移动的源文件生命周期、底层操作不同。 |
| 4 | `zoom_in` / `zoom_out` | 保留。上限 20、下限 8，方向不同，各自只有几行逻辑。 |

## 后续需要继续核查的范围

以下并未因为本轮候选检查结束就视为完成：

1. 报告输出路径与模板定位：旧协调器 `_build_document_paths` 和 Word `_init_report_paths` 仍有重复片段，但还混合 CSV 路径、日期回退、兼容属性、日志差异。需要单独确认外部属性使用和异常行为，再决定共享计算还是删除旧协调器中不再需要的准备工作。
2. 跨模块业务规则：优先核对电流/电压单位换算、文件发现、配置默认值与迁移、日期解析、统计计算是否都有单一权威来源。这些需要按数据流语义核查，不能靠本扫描器排除重复。
3. 运行时占用：用真实大批量 NDAX 数据测量导入、分析、绘图和导出的耗时/峰值内存，再针对热点减少重复读取、转换或缓存。不在本轮凭代码行数宣称性能收益。
